# 总实施蓝图：先证明单项目交付，再证明产品复用

版本：1.0｜性质：P0详细计划的上位路线图；P1以后须再细化并批准。

## 1. 产品完成定义

生产级不是自动通过审批，也不是系统代替责任人签署。它意味着：针对声明支持的项目类型和适用规则，输入资料经过确认，技术过程可复算，关键结论有证据，文表图附件一致，独立水保工程师无需结构性重写即可完成校审，能够形成符合要求的交付文件。

分别标识：ENGINEERING_ACCEPTED（软件验收）、TECHNICALLY_REVIEWED（专业校审）、RELEASED（项目成果发布）、APPROVED_BY_AUTHORITY（实际审批状态）。前者不自动推出后者。

## 2. 路线与退出条件

| 阶段 | 要完成的成果 | 主要依赖 | 退出条件 | 不能声称什么 |
| --- | --- | --- | --- | --- |
| P0 可信度底线 | 诚实的缺口/质量报告、受控草稿、正式发布门禁、可靠冻结标识 | 本任务包RFC | 反例矩阵通过、所有入口无静默降级、原测试回归 | 已能生产完整报告 |
| P1 黄金项目与内容规范 | 一个真实项目资料包、适用版本、逐章论证/图表清单、人工确认的目标成果 | 项目资料与专业负责人 | 输入和专业工作缺口明确；所有必需成果有负责人和验收定义 | 只有成稿PDF就已获得完整输入 |
| P2 技术生产闭环 | 项目组成/分区/时段、土石方与表土、措施设计、工程量、投资、预测效果、引用与专业复核 | P1、相关专项方法确认 | 每条关键结果能复算；同一措施贯穿文表图；关键断点归零 | 有默认系数就等于完成工程设计 |
| P3 完整报告与交付 | 正文、责任页、目录、计算、附图附表附件、空间成果、校审版本和发布记录 | P2及真实图件/签署材料 | 逐页QA、独立专业校审、完整性检查全部通过 | 软件保证行政许可 |
| P4 独立项目验证 | 至少第二个未参与调试的同类项目，另加边界案例 | P3 | 可重复交付，人工工时可量化，重大质量缺陷不增加 | 一个项目定制完成就是全行业覆盖 |

关键路径：`P0 → P1确认 → P2技术闭环 → P3完整交付 → P4复用验证`。P0期间可以人工收集P1资料，但不得将未确认资料自动写入生产facts。

## 3. 范围选择

第一支持范围建议：广东/惠州、单一行政区、点型工业/园区/仓储类建设项目，完整新编方案。必须先确认报告书/表的法律物种，不能因为某个renderer能用而反推项目物种。

不直接承诺：跨省多规则、高风险弃渣场失事专题、复杂边坡稳定、矿山生产期、多期复杂变更、全行业自动推荐。遇到这些情况，明确需专项工具/成果/专业责任人，不靠长文本覆盖。

现有惠阳启沃智谷成稿可作为目标表达参考，但黄金项目最终选择取决于能否取得原始设计和可核验资料，不由文件名直接决定。

## 4. 架构演进：利用现有资产，而不是平行重建

| 能力 | 现有资产 | 演进方向 |
| --- | --- | --- |
| 字段与投影 | FIR、ProjectFactSheet | 统一读上下文；来源/版本附着于字段；清除别名和多入口差异 |
| 义务与适用性 | ConditionEngine、ObligationSet | 已知/未知/错误显式化；保持规则输出义务，不输出UI |
| 分区与措施 | PreventionSystem三大真源 | 扩展已确认的设计参数、空间/时序引用；投资仅消费 |
| 计算 | CalculatorRegistry、prediction_engine、投资计算 | 方法适用性、参数依据、单位、精度、输入hash、计算状态齐全；缺条件不回退伪值 |
| 专业评价 | NarrativeTemplateSpec、NarrativeBlock | 上游论证记录驱动结论；正文只组织已确认事实与判断 |
| 制品 | ArtifactRegistry、TableData、GeoPipeline | required/provided/validated分离；生成和人工导入统一纳管 |
| 文档 | document renderer、DisplayNumberingPolicy | ReportSpec+统一文档块；编号晚绑定；正文与附件装配 |
| 审查修改 | ReviewComment、FactDiff、ModificationReport | 意见→责任项→修改→重算→复核→关闭；不能只改resolved字符串 |
| 交付 | FrozenSubmissionInput、PackageVersion、ExportGate | 明确草稿和正式发布；完整输入冻结、依赖失效、发布事务 |

P0不实现通用自然语言事实证明器。程序可以验证引用解析、单位、数值绑定、计算状态和一致性，不能仅凭这些证明某句专业论证正确。技术正确性需要受控评价方法和专业校审。

## 5. P1：先建立内容规范，再补模板

每个内容单元登记：稳定ID、适用条件、所回答问题、必需输入、证据要求、计算/评价方法、结论允许范围、表图附件、复核角色、阻断条件。此处是ReportSpec的内容合同，不是“每节至少500字”。

逆向拆解顺序：项目事实（第2章）→评价（第3章）→表土（第4章）/弃渣及临时堆土（适用时第5章）→预测（第6章）→防治措施（第7章）→监测（第8章）→投资和效果（第9章）→管理（第10章）→综合说明（第1章最后生成）。不是简单按目录从前写到后。

ReportBook和ReportForm使用不同成果结构；已公开报告表附很长技术正文，不意味着所有报告表依法要求十章长篇。以项目适用正式模板和地方有效要求为准。

## 6. P2：最小专业闭环工作包

### P2-A 土石方/表土

分清总挖填、含/不含表土、自然方/松方等体积口径；分区分期的源—去向、借弃、临时堆存、容量与调运时序；表土调查点/厚度/质量、剥离与就地保护、堆存养护、回覆需求、外借及剩余利用支撑材料。守恒式须先确认各字段包含关系，不能把综合利用方与弃方重复相加。

### P2-B 措施与工程量

复用措施真源，区别主体已有、方案新增、未纳入水保措施。每个纳入措施绑定分区、空间、设计标准、计算或主体设计引用、尺寸、工程量、实施时序、典型图号。第一轮只覆盖黄金项目实际需要的措施类型，禁止边做边承诺所有措施自动设计。

### P2-C 预测/效果/投资

预测按项目适用方法、分区、时段和地表状态计算；工程完工硬化面积不能机械进入自然恢复期。六项指标分别确认公式、分子分母及不适用条件；目标、设计效果、实测结果分别保存。投资从相同工程量与已确认单价/费率计算，明确主体已有/新增、地区、价格时点及精度。

### P2-D 评价记录

先做可审查的论证卡：问题、条款、项目证据、方法、结果、备选与优化、结论、限制、复核。重大专业判断不能因为某个obligation触发就标为已完成。必要时由工程师录入已审专项成果，系统负责引用和一致性，不伪装自动计算。

## 7. P3：完整文档装配和发布

统一块类型至少包括Paragraph、Table、Equation、Figure、Attachment、CrossReference；以stable ID驱动编号、目录、页码和引用。图件包括真实底图/矢量边界、适当比例尺、坐标系、制图信息、措施/监测点和相关范围；正式图片与可交付空间文件都要验收。

应验证封面/扉页/责任页、双面装订、两级目录、中文/西文字体、章页眉、页脚、表头重复、横向宽表、附图分节、公式、附件顺序、引用页码。以适用规范为准，不能把蓝色标题理解成湖蓝封面，也不能把DOCX自动当成DOC要求已经满足。

签字盖章流程应是：编制/校审草稿→签署用定版→真实签署材料纳入→最终包完整性和hash核验→正式发布。允许生成未签署的校审/签署草稿；不能要求“先正式发布才能签署”，形成循环依赖。签名真实性和专业责任仍由实际责任人承担，软件只记录证据和确认。

导出后的人工Word修改会使原发布校验不再适用；修改文件必须作为新版本重新导入、对照和复核，不能继续使用旧的“校验通过”标识。

## 8. P4：验证和指标

建议记录而不提前承诺降幅：补资料轮次、编制实际工时、校核工时、重大/一般技术问题数、跨章节不一致数、需手工修改的图表数、修改意见复核关闭率、重复项目配置工作量。

重大技术错误、无依据肯定结论、必需资料缺失、虚假签署、关键数量不一致，均为一票否决项，不与排版分数平均。完整度、证据就绪度、技术校审状态、页面质量分别展示，不用一个总分掩盖短板。

人工验收建议至少两种角色：熟悉项目的编制工程师确认事实；未直接参与生成的校审工程师审查技术成果。有条件再组织真实送审反馈，但审批进度不作为软件自动证明。

## 9. 工作量与资源

不按模型运行时长承诺工期。P0约10个小任务、3次批次验收；每次以代码差异和测试证据为单位。P1—P3需要持续可用的水保工程师，空间/设计/造价问题需要相应专业能力，实际周期主要取决于资料与复核资源。

没有原始资料时，Claude可以完成P0、P1清单和接口设计，不能宣布黄金报告交付完成。P1退出后再给P2拆文件级任务和估时，避免用未经验证的大计划固定全部实现。

## 10. 阶段决策记录

每个阶段结束，记录：已验证能力、未验证能力、未解决风险、人工补做工作、下一阶段必需条件、批准的范围变化。不要使用“全部完成，后续优化”掩盖生产必需项尚未实现。
