## 交付目标

先修复报告可信度底线，再以一个真实、资料齐全的广东点型项目完成专业校审交付，最后用独立项目验证复用能力。第一阶段不承诺自动完成报告、不承诺通过审批。

本任务包交给 Claude 实施。Claude 负责代码和自动验证；项目负责人决定范围；水保工程师负责资料、技术判断与专业校审；独立复核者依据测试和实际成果验收。作者、执行者和专业签署者不能混同。

## 如何开始

1. 将整个项目及本目录交给 Claude，不要只复制总蓝图。
2. 发送 `06_CLAUDE_HANDOFF.md` 中的“启动提示词”。先核查基线和 RFC；本轮“编制计划”不等于已批准改代码。
3. 确认 RFC 后，按 A / B / C 三批实施 P0。每批提交验收材料后停止，等反馈再继续。
4. P0 通过只表示：系统能够诚实暴露缺口、阻止不可信正式交付；**不表示已经能产出生产级报告**。
5. P1 开始前选择黄金项目并确认资料清单，再细化 P1 的代码任务；不得把远期蓝图当作整仓重写授权。

## 不允许用来“完成”任务的方式

- 补写假的项目事实、现场调查、来源、签名、盖章或专业确认。
- 用模板覆盖率、字数、页数、测试数量替代技术质量。
- 删除失败测试、批量更新快照，或降低门禁使结果变绿。
- 把示意图、典型值、合成夹具、历史样稿数据包装成项目生产成果。
- 创建新的措施事实副本，绕过现有 PreventionSystem 真源契约。
- 未经批准激活 `registries/reserved/`，或扩大到 SaaS、计费、用户体系、模型平台。
