# B 批：剩余 18 个模板的逐模板改造清单

版本：1.0｜编制日期：2026-09-20｜状态：**待批准**（B 批本身尚未批准）

来源：A 批验收意见——"剩余 18 个模板：同意与 B 批 BuildContext 一起改造。将其列成明确的逐模板任务和验收项，覆盖缺失、明确零、非法值、来源冲突四类输入。不能只替换 `_v`/`_num` 函数名，也不能因为未标 `PROJECT_JUDGMENT` 就认定正文没有专业判断。"

## 0. 为什么不能只换函数名

`_v(facts, key, default="—")` 换成 `SectionEvidence.text()` 只解决了"缺失显示成什么"。它**不**解决：

| 只换函数名解决不了的 | 必须逐模板判断的 |
| --- | --- |
| 明确填 0 与没填的业务含义分别是什么 | 例：占地面积 0 是"不占地"还是"没测"？监测点数 0 是"不设点"还是"没规划"？ |
| 哪些数值参与了运算、除零怎么办 | 例：`sec_6_soil_loss` 的模数×面积×时段；`sec_7_1` 的分县面积占比 |
| 正文里哪些句子其实是专业判断 | **未标 `PROJECT_JUDGMENT` 不等于没有判断**。A 批就是靠逐句读出来的，不是靠标记 |
| 两个来源给了不同的值时选哪个 | P0-04 的别名表落地后才谈得上（`DECISION_LOG` 条目 003） |

因此每个模板的任务是**三件事**：①接 `BuildContext`/`SectionEvidence` ②逐句判定断言类型 ③补四类输入的回归测试。

## 1. 统一验收项（每个模板都要过）

每个模板必须有一组覆盖下列四类输入的测试，测试文件建议 `tests/test_template_<module>.py`：

| 编号 | 输入 | 必须观察到 |
| --- | --- | --- |
| T-a | 相关字段**全缺** | 无肯定结论；缺口段列出具体 field id；正文不出现"—"冒充数据；至少一条 `VALUE_MISSING` 且带 `missing_input_refs` |
| T-b | 相关字段**明确填 0 / 空清单 / False** | 复述填报值（可以说"填报为 0"）；**不得**升级为业务结论（"不涉及""无需""不设置"）；此类结论走 `judgment()` |
| T-c | **非法值**（NaN、inf、`"NaN"` 字符串、未登记单位、Quantity 空值） | 判 `VALUE_INVALID`；非法值不参与任何运算；正文不出现该数字 |
| T-d | **来源冲突**（同一语义两个别名都有值且不等） | 判 `INPUT_CONFLICT`；不静默择一；正文说明冲突并停在待确认 |

补充两项通用检查：

- **T-e 断言类型逐句核对**：模板产出的每个 `NarrativeParagraph` 都必须显式设置 `assertion_class`。审查人逐句确认分类正确——尤其确认没有"看起来像陈述事实、实际是专业判断"的句子被标成 `FACT_RESTATEMENT`。这一项**必须人工做**，不能由测试代替。
- **T-f 契约校验**：`validate_block` 返回空；任何 `PROJECT_JUDGMENT` 段落都带 `review_refs`。

## 3. 与 P0-04 / P0-05 的依赖关系

- **必须先有 `BuildContext`（P0-04 第 1 条）**：否则 18 个模板会各自拿 `facts`/`derived` 两个 dict，和 A 批已改造的 9 个模板形成两套取值路径。
- **必须先有别名表（P0-04 第 2 条 + `DECISION_LOG` 条目 003）**：T-d（来源冲突）这一类验收项在别名表落地前无法构造真实用例。
- **必须先解决 `DECISION_LOG` 条目 007**：正文/表格当前读不到样本的 pre-stored derived，18 个模板中凡依赖 `field.derived.*` 的（B-T3、B-T5、B-T6）在修好合并口径前，测不出真实行为。
- **B-T12 与 P0-05 协调**：设计水平年在 2026 模板中的位置属 P0-05 的核对范围，避免两批互相覆盖。

## 4. 不做的事

- 不为了让模板"看起来完整"而补写套话或按字数填充。
- 不在本批引入新的计算器或业务公式（六率效果管线仍不在范围内）。
- 不因为某模板没有 `PROJECT_JUDGMENT` 标记就跳过 T-e 的人工逐句复核。
